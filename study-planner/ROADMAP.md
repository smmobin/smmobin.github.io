استریک خارج است. ترتیب زیر **مسیر اجرایی پیشنهادی PM** است و تعارض «جداسازی ریپو اول» را با **جداسازی منطقی داخل همین مخزن** حل می‌کند (نه دو GitHub جدا قبل از API پایدار).

## موج F — دو ریپو / انتشار (دیرتر)

فقط وقتی قرارداد API دیگر هر هفته عوض نمی‌شود (پس از موج C ترجیحاً). تا آن روز: monorepo با `apps/web` + `apps/api`.

## تصمیم‌های قفل‌شدهٔ زیرساخت

- بک: API خودمان + Postgres محلی (نه کلاینت مستقیم Supabase)
- Auth: JWT ~۱۵دقیقه + refresh ~۳۰روز با rotation
- چت: فقط جفت متصل؛ فایل روی دیسک API تا ۲۰مگ
- سطح: فرمول دقیقهٔ ۳۰روز در STATUS
- دمو لوکال می‌تواند موقتاً بماند تا API جایگزین شود؛ هدف نهایی یک بک است

## اصول

1. یک موج = یک هدف قابل‌دمو  
2. امنیت نقش در API، نه فقط UI  
3. رمز و اسرار فقط `.env.local`  
4. «همه با هم» ممنوع — صف FEATURES را موج‌موج مصرف کن  
5. با vibe coding می‌توان موج‌ها را **سریع پشت‌سرهم** زد؛ حذف موج A (اسکلت API) مجاز نیست حتی اگر هزینه مهم نباشد
