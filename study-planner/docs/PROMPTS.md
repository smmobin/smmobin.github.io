## هدف موج A (فقط این‌ها)
1) اسکلت API خودمان روی Postgres محلی (نه Supabase مستقیم از فرانت).
2) اتصال از `.env.local` موجود (gitignore است؛ رمز را در چت چاپ نکن؛ اگر متغیر کم است نام متغیر را بگو نه مقدار).
3) JWT: access ~۱۵ دقیقه (حافظهٔ کلاینت) + refresh ~۳۰ روز با rotation (ترجیحاً httpOnly cookie یا معادل امن مستندشده).
4) فرانت فقط با HTTP به همین API حرف بزند؛ مسیر اصلی `@supabase` را از جریان فعال خارج کن.
5) مرز منطقی داخل همین ریپو: ترجیحاً `apps/api` + `apps/web` (یا معادل واضح). دو GitHub جدا نساز.
6) حداقل endpointها: health، ثبت‌نام/ورود دانش‌آموز ساده، me، refresh، logout — کافی برای دود تست.
7) شکستن تدریجی App.tsx را شروع کن اگر جلوی اسکلت را نمی‌گیرد؛ کامل اجباری نیست.
8) یک تست دود برای health (+ در صورت امکان یک تست واحد کوچک).

## واقعیت کد الان (باید بدانی)
- مشاور روی API جدید: `advisorNotReady()` در `apps/web/src/cloud.ts` — endpoint مشاور روی `apps/api` نیست.
- مهمان هنوز در AuthGate/App هست.
- دعوت فقط بعد از ورود در تب «بیشتر»؛ هنگام ثبت‌نام کد نیست.

## هدف موج B (همه روی API خودمان + فرانت)
1) حذف کامل مهمان محلی از UI و جریان اصلی.
2) فرم دانش‌آموز واحد: ثبت‌نام/ورود + فیلد کد دعوت اختیاری.
   - خالی = مستقل
   - غلط/منقضی/مصرف‌شده = ثبت‌نام مسدود با پیام فارسی واضح
3) اتصال با کد از تب «بیشتر» بعد از ورود هم بماند.
4) قطع رابطه دو طرفه (دانش‌آموز و مشاور)؛ بعد از قطع داده بماند و قفل plan/subjects/نام/تایمر باز شود.
5) جدول/API دعوت و رابطه مشاور↔دانش‌آموز روی Postgres (migrate جدید اگر لازم).
6) endpointهای مشاور روی API: لیست دانش‌آموزان، ساخت دعوت، ذخیرهٔ plan/subjects/weeklyGoal، ساخت/ویرایش/حذف بلوک، ساخت تسک؛ دانش‌آموز متصل فقط تیک تسک + sessions/تایمر (نام و focus/break قفل).
7) UI مشاور: CRUD بلوک + ساخت تسک (نه فقط افزودن یک‌طرفهٔ قبلی).
8) باگ AuthGate: `initialError` تکراری را حذف کن؛ portal pickers را در حد معقول بهبود بده.
9) حذف `streakDays` از کد.
